# Project Structure

## Root Layout

```
manifest.json        # Chrome MV3 manifest — permissions, entry points, host_permissions
popup.html           # Minimal shell — just <div id="root">, loads dist/popup.js
vite.config.ts       # Build config — defines the three entry points, includes React plugin
tsconfig.json        # TypeScript config — strict, ES2022, bundler resolution, jsx: react-jsx
package.json
icons/               # Extension icons at 16, 48, 128px
dist/                # Build output (gitignored) — loaded by Chrome
src/                 # All source TypeScript/TSX
```

## src/ Modules

### `src/analysis/` — Pure scoring logic, no DOM dependencies

| File | Responsibility |
|---|---|
| `types.ts` | Shared types: `PromptIntent`, `IntentScores`, `QualityScores`. `QualityScores` has six fields: `autonomy`, `curiosity`, `criticalThinking`, `specificity`, `context`, `iteration` — `iteration` is fixed at 50 and excluded from the real-time score. |
| `classifier.ts` | Signal-based intent scoring (`scoreIntents`, `primaryIntentFrom`). `explain`, `analyze`, `identify`, `review`, `suggest`, `provide` are delegation signals (task verbs), not curiosity signals. `primaryIntentFrom` accepts optional `text` param — if delegation is within 1 signal of the winner and the prompt contains role-setting (`you are`, `act as`, `your task`, `your role`), delegation wins the tie-break. |
| `stopWords.ts` | Exported `STOP_WORDS` set — filtered out before TF-IDF topic extraction. Re-exported from `engine.ts` for backward compatibility. |
| `idfTable.ts` | Exported `WORD_IDF` record — pre-computed IDF proxy table (~500 entries, grouped by frequency tier). Covers CS/software, medicine/biology, physics/chemistry, mathematics/statistics, ML/AI, law, finance/economics, psychology, linguistics, history/social sciences, and engineering. Imported by `tfidf.ts` only. |
| `rubric.ts` | Flag detection and quality scoring (`detectFlags`, `scorePromptQuality`, `computeQualityScore`). Internally composed of four helpers: `computeBaseScores` (starting values by word count), `applyFlagBonuses`, `applyIntentBonuses`, `applyPenalties`. `computeQualityScore` is intent-aware: delegation weights autonomy×0.30, criticalThinking×0.25, curiosity×0.15, specificity×0.15, context×0.15; curiosity intent weights curiosity×0.30, autonomy×0.20, criticalThinking×0.20, specificity×0.15, context×0.15; all other intents use equal weights across all five dimensions. `iteration` is always set to 50 and excluded from all weighted scores. Long delegation penalty (`wordCount>120, no ?`) only fires when the prompt lacks structure signals. `copy_paste_without_question` flag fires for any intent (not just delegation) when `wordCount>100`, no `?`, and no structure signals present. `CONTEXT_SIGNALS` includes: `constraints`, `requirements`, `audience`, `format`, `rubric`, `example`, `goal`, `context`, `background`, `best practices`, `behavior`, `behaviour`, `use case`, `scenario`, `criteria`. **Intent excellence scoring**: `computeExcellenceBonus()` runs after base scoring and applies graduated bonuses (up to +25 pts) to the dimensions most relevant for each intent — delegation (6 signals), curiosity (5), collaborative (5), verification (5). Bonus scales linearly with ratio of signals hit. High-excellence prompts (ratio ≥ 0.6) without `?` have the no-question curiosity penalty partially restored (+10). |
| `tfidf.ts` | Adapted TF-IDF topic extraction. Imports IDF table from `idfTable.ts`. `scoreToken` is a module-level pure function (takes `totalWords` as param). Finds all **contiguous spans** of non-stop words, scores each by average TF-IDF (position weight, technical boost, qualifier penalty), and returns the best-scoring span as a coherent noun phrase. Exports: `extractTopicTFIDF(text, stopWords)` — single best phrase; `extractTopicsTFIDF(text, stopWords, n)` — top N **non-overlapping** spans. All multipliers (`POSITION_WEIGHT`, `TECHNICAL_BOOST`, `QUALIFIER_PENALTY`, `UNKNOWN_WORD_IDF`, `MAX_TOPIC_WORDS`) are exported constants. |
| `engine.ts` | Public API — `analyzePrompt(text): LiveScore` — composes classifier + rubric into UI-ready scores. Imports `STOP_WORDS` from `stopWords.ts` and re-exports it. `LiveScore` dimensions: `ownership`, `depth`, `critical`, `clarity`. Calls `extractTopicsTFIDF` to get up to 3 distinct topic phrases, then assigns a different phrase to each suggestion builder (`ownershipSuggestion`, `depthSuggestion`, `criticalSuggestion`, `claritySuggestion`) so tips reference different parts of the prompt. Weak dimensions (score < 60) sorted ascending; top 3 returned. |
| `ai.ts` | Thin proxy — `scoreWithAI(text, heuristic?)` sends an `AI_SCORE` message (with optional `HeuristicContext`) to the background worker and returns the result. `HeuristicContext` carries pre-computed intent, flags, dimension scores, TF-IDF topics, and `displayedScore`. Does not fetch directly (content scripts on https:// pages cannot make http:// requests — Chrome mixed-content block) |

### `src/content/` — Injected into AI platform pages

| File | Responsibility |
|---|---|
| `index.ts` | Entry point — detects platform, polls for input element, attaches observers via `attachToInput()`, debounces analysis, sends messages to background. Two-layer scoring: heuristic fires at 300 ms debounce, AI async re-score fires at 1500 ms debounce. Score blending, soft-floor, auth state, and SPA navigation detection. Imports from `./overlay` facade. |
| `selectors.ts` | `PlatformConfig` type + per-platform DOM selectors for ChatGPT, Gemini, Perplexity, Claude. Carries optional placement fields: `plusButtonSelector`, `badgeGap`, `badgeNudgeY`, `pillNudgeY`. |
| `theme.ts` | **Design tokens for content-script overlays** — single source of truth for brand colors, score colors, pill colors, glass surfaces, shadows, typography, layout sizes, z-indices, and DOM IDs/classes. Content scripts inject styles into host pages so CSS custom properties aren't reliable; these TS constants serve the same purpose and can be swapped for theming. |
| `dom-utils.ts` | Shared DOM helpers — `svgEl()` (SVG element factory), `injectGlassDefs()` (gradient defs), `buildCircleSvg()` (reusable arc-ring circle), `findInputBar()`, `findPlusButton()`, `positionBadge()`, `waitForPlusButtonAndReposition()`. |
| `badge.ts` | Main score badge — `renderOverlay()`, `hideOverlay()`, `setBadgeLoading()`, `setDetailedMetricsEnabled()`. Creates/updates the floating badge SVG, animates score number (280 ms ease-out cubic), manages pulse styles. |
| `bubbles.ts` | Metric bubble circles — `showBubbles()`, `hideBubbles()`, `setCurrentScore()`. The 4 vertical metric circles that stack above the badge on hover with staggered entrance animation and "OVERALL" label. |
| `pills.ts` | Feedback pills — `renderFeedback()`, `renderLoginPrompt()`, `hideFeedback()`, `attachInputBarHover()`. Pending state management, suggestion pills (red/green), login CTA pill (purple), and transparent bridge for hover continuity. |
| `overlay.ts` | **Facade** — re-exports the public API from `badge.ts` and `pills.ts` so `index.ts` imports remain unchanged. |

### `src/background/` — Service worker

| File | Responsibility |
|---|---|
| `index.ts` | **Message router** — receives `SCORE_UPDATE`, `PROMPT_SUBMITTED`, `AI_SCORE`, `OAUTH_SIGN_IN`, `SETTINGS_UPDATE`, and `GET_LATEST_SCORE` messages and dispatches to focused modules. Tracks `latestScore` and `activeSettings`. Re-exports `derivePlatform` for test access. |
| `auth.ts` | Session management — `StoredSession` type, `jwtExpBg()`, `getStoredSession()`, `isTokenExpiringSoonBg()`, `refreshStoredSession()`, `getValidAccessToken()`, `handleOAuthSignIn(provider)`. All Supabase Auth interactions live here. |
| `ai-proxy.ts` | AI scoring proxy — `SYSTEM_PROMPT` constant, `buildPreAnalysis(heuristic)`, `fetchAIScore(text, heuristic?)`. Streams SSE from Fly.dev, handles 401 retry with token refresh, parses and clamps response. |
| `prompts.ts` | Prompt storage — `derivePlatform(url)`, `insertPromptRow(message, senderUrl)`. Writes scored prompts to `extension_prompts` via Supabase REST. |

### `src/popup/` — Extension popup (React)

| File | Responsibility |
|---|---|
| `main.tsx` | Entry point — mounts `<App />` wrapped in `<ErrorBoundary>` into `#root` via `createRoot`, imports `tokens.css` then `popup.css` |
| `tokens.css` | **Design tokens** — CSS custom properties (`:root`) for brand, surfaces, borders, text, semantic colors, radii, spacing, typography, and effects. Future themes override these variables under `[data-theme="light"]` etc. |
| `popup.css` | All popup styles — imports `tokens.css`, uses `var(--m-*)` tokens throughout |
| `auth.ts` | Supabase auth functions: `loadSession`, `saveSession`, `signInWithPassword`, `signOut`, `signInWithOAuth`, `fetchLifetimeStats`, `refreshSession`, `getValidSession`, `deleteAllPrompts`, `aggregateStats`. All calls are direct `fetch` to Supabase REST — no SDK. `refreshSession(session)` exchanges a refresh token for a new access token and persists the result. `getValidSession()` loads the stored session and silently refreshes it if the access token expires within 5 minutes (5-minute buffer). Exports `AuthSession` and `LifetimeStats` types. `fetchLifetimeStats(accessToken)` queries `extension_prompts` directly — RLS scopes to current user. `aggregateStats(rows)` is a pure exported function that computes stats from the raw rows. `LifetimeStats` shape: `{ totalPrompts, avgScore, topPlatform, wordCountBuckets: {short,medium,long,total}, scoreBands: {excellent,good,needsWork}, intentCounts: {delegation,curiosity,collaborative,verification}, platformStats: Record<string,{count,avgScore}> }`. `wordCountBuckets` built from `extension_prompts.word_count` column. `deleteAllPrompts(accessToken)` deletes all the user's `extension_prompts` rows (RLS-scoped, requires `user_id` filter as safety net). |
| `settings.ts` | Settings persistence: `loadSettings`, `saveSettings`, `Settings` interface, `DEFAULT_SETTINGS`. `Settings` fields: `pillsEnabled`, `badgeEnabled`, `statsEnabled`, `detailedMetricsEnabled`. `DEFAULT_SETTINGS.detailedMetricsEnabled = false`. `saveSettings` broadcasts `SETTINGS_UPDATE` to all content scripts. |
| `components/App.tsx` | Root component — manages `activeTab` (default: `'account'`), `session`, `settings`, `ready`, and `statsReloadKey` state; on mount calls `getValidSession()` (silently refreshes token if expiring) and `loadSettings()` in parallel, setting `ready = true` on completion (or after a 3 s timeout so the UI never stays blank in slow environments like E2E); renders header with platform logo badge (`PlatformBadge` — inline SVG for ChatGPT/Gemini/Perplexity/Claude, hidden when inactive), tab bar, and two tab panels. Tab panels are only rendered once `ready` is true. **Settings tab is hidden when the user is signed out** — only the Account tab is visible when unauthenticated. On sign-out, `activeTab` snaps back to `'account'` via a `useEffect` watching `isSignedIn`. Tab order: Account, Settings. `statsReloadKey` is incremented by `SettingsTab.onDeleteDone` to trigger an `AccountTab` stats reload after data deletion. |
| `components/ErrorBoundary.tsx` | Class-based React error boundary — catches render errors and shows a retry UI. Wraps `<App />` in `main.tsx`. |
| `components/SettingsTab.tsx` | Pills/badge/detailed-metrics toggles with React state; calls `saveSettings` on change; shows saved toast. "Detailed metrics" is a sub-setting nested under "Score badge" (disabled when badge is off) — controls whether the 4 scoring dimension bubbles appear on badge hover. Includes an inline expandable "?" tip section showing colour-coded metric definitions (replaces the former standalone TipsTab). Stat-collection toggle is only rendered when the user is signed in. Reset to defaults button. When signed in, also shows a "Delete my data" button with a two-tap confirmation flow — calls `deleteAllPrompts` and triggers a stats reload via `onDeleteDone` prop. |
| `components/AccountTab.tsx` | Auth UI — signed-out: email/password form + Google/GitHub OAuth buttons; signed-in: `SignedInView` with user card, borderless stat rows (`StatRow` — label + large value + caret, hover tint animation), and sign-out button. Stats polled every 10 s while popup is open. On session load, calls `getValidSession()` before fetching stats to refresh stale tokens, and propagates the refreshed session back up via `onSessionChange` if the token changed. Clicking a stat row navigates to a detail panel (`detail` state: `'prompts' \| 'score' \| 'intents' \| 'platform'`) with a back button. Detail panels: `PromptsDetail` (word count distribution — Short/Medium/Long CSS horizontal bars with count + % from `extension_prompts.word_count`), `ScoreDetail` (score band distribution — excellent/good/needs work), `IntentsDetail` (per-intent prompt counts and percentages), `PlatformDetail` (per-platform prompt count + avg score). `computeTopIntent(intentCounts)` is an exported helper used for the "Top intent" stat row value. |

## Key Architectural Rules

- `src/analysis/` must stay DOM-free and platform-agnostic — it can be unit tested in isolation
- `src/content/` is the only layer that touches the page DOM
- Message passing between layers uses typed discriminated unions (`type: 'SCORE_UPDATE' | 'PROMPT_SUBMITTED' | 'GET_LATEST_SCORE' | 'AI_SCORE' | 'SETTINGS_UPDATE'`)
- The overlay (`overlay.ts`) manages its own state (`currentScore`, `bubblesVisible`, `feedbackVisible`, `pendingSuggestions`, `pendingScores`, `pendingInputEl`, `pendingPlatform`, `pendingLoginPrompt`, `inputBarHoverEl`, `mouseInsideInputBar`, `badgeLabelRemoveTimeout`) as module-level variables — there is no external state store. `badgeLabelRemoveTimeout` tracks the pending `setTimeout` that removes the OVERALL label after fade-out; cancelled on re-hover to prevent duplicate label creation.
- Platform selectors live exclusively in `selectors.ts` — never hardcode selectors elsewhere
- All scores are integers 0–100, clamped via `clamp()` in `rubric.ts`
- The `LiveScore` interface (defined in `engine.ts`) is the single contract between analysis and UI layers
- **Two-layer scoring**: heuristic (`engine.ts`) fires instantly at 300 ms debounce; AI (`ai.ts`) fires async at 1500 ms debounce and merges over the heuristic result. AI failures are silent — heuristic score remains. Badge border pulses purple 600 ms after heuristic fires to signal AI scoring is pending; pulse cancels immediately if user resumes typing. **Feedback pills are stored as pending state** when AI (or heuristic fallback) responds — they render only when the user hovers the input bar (`mouseenter`) and hide on `mouseleave`. If the mouse is already inside the input bar when feedback arrives, pills show immediately. Pending state is cleared when the user starts typing a new prompt **or when the input is emptied** (text < 5 chars — `hideFeedback(true)` is called, clearing all pending state so hovering an empty bar shows nothing). `attachInputBarHover` is called once per input attach in `index.ts`. When merging AI scores, if AI returns empty suggestions the heuristic suggestions are used as fallback so pills always have content.
- **Settings persistence**: user settings (`pillsEnabled`, `badgeEnabled`, `statsEnabled`, `detailedMetricsEnabled`) are stored in `chrome.storage.sync`. `DEFAULT_SETTINGS.detailedMetricsEnabled = false`. Popup broadcasts `SETTINGS_UPDATE` to all tabs via `chrome.tabs.sendMessage` on change; content script applies changes immediately via module-level `contentSettings` object (`ContentSettings` interface — `pillsEnabled`, `badgeEnabled`, and `detailedMetricsEnabled`; `statsEnabled` is not forwarded to content scripts — the background worker re-reads it from storage directly on each `PROMPT_SUBMITTED`). Toggling badge off calls `hideOverlay()` instantly; toggling on re-triggers `onInputChange`. Toggling pills off calls `hideFeedback(true)` instantly. Toggling detailed metrics off calls `setDetailedMetricsEnabled(false)` which hides the metric bubbles. `renderOverlay` and `renderFeedback` calls in the scoring flow are gated by `contentSettings.badgeEnabled` / `contentSettings.pillsEnabled`.
- **Auth**: Supabase Auth email/password + OAuth (Google, GitHub) flows live in `src/popup/auth.ts`, consumed by `AccountTab.tsx`. Email/password calls `/auth/v1/token?grant_type=password`. OAuth uses `chrome.identity.launchWebAuthFlow` — redirect URL is `https://<ext-id>.chromiumapp.org/auth` (hardcoded https scheme to avoid Arc on Windows issues), which must be added to Supabase Dashboard → Authentication → URL Configuration → Redirect URLs. Tokens are parsed from the redirect URL fragment. `getValidSession()` silently refreshes the access token via `/auth/v1/token?grant_type=refresh_token` if it expires within 5 minutes — called on popup mount and before stat fetches. All auth calls are direct `fetch` to Supabase — no SDK. Session stored in `chrome.storage.local`. `"identity"` permission required in `manifest.json`.
- **Supabase backend**: hosted project `anmsstuexchqyghqoipt`. Primary extension table: `extension_prompts` — stores per-prompt scores, intent, platform, word_count, user_id; RLS-scoped. Legacy tables (`analysis_history`, `chat_histories`) exist but are no longer queried by the extension. Fly.dev backend (`https://mentro-lucid-dust-3580.fly.dev`) is a separate server; auth bypasses it and goes directly to Supabase Auth.
- **AI fetch lives in the background worker** (`background/index.ts`), not in the content script. Content scripts on https:// pages cannot make http:// requests (Chrome mixed-content block). `ai.ts` is a thin message-passing wrapper only.
- **AI system prompt** uses anchored scale descriptions (0/40/70/100 examples per dimension) and five calibration examples — vague prompt ("test test test", scores ~4), short delegation ("fix my code", scores ~10), medium-quality curiosity prompt (BFS in Python, scores ~44), high-quality structured delegation prompt (FlickIt MVP, scores ~76), and high-quality structured delegation with requirements list and no question marks (academic essay, scores ~69) — covering the full quality range and explicitly teaching the model not to penalize imperative phrasing when requirements are clearly listed. Suggestions rules: must reference only topics present in the prompt (never invent topics), be a concrete question the user could literally add, target a different weak dimension each, with good/bad examples. Hard constraint: `CRITICAL: suggestions must only reference topics that appear in the prompt`.
